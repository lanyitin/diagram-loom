# 從一段資料建出 diagram-loom 模型

## 先讀懂這個工具在乎什麼

它不是畫圖工具，是**防漏工具**。使用者的痛點是「接下來要處理的系統有數百條
連線，怕漏」。所以你的目標不是「建得快」，是**建得完整，而且漏掉的地方會被指出來**。

`lint` 是你的自我檢查。**每建完一批就叫一次。**

## 兩層模型

| | | |
| --- | --- | --- |
| **邏輯層** | 母版，定義一次 | 系統、服務、接點定義、契約、人 |
| **環境層** | 分身，每個環境一份 | 環境、機器、落地、設備、連線 |

**通則：邏輯層有的東西，每個環境都必須實現。** 沒實現就是 lint 錯誤。
這就是為什麼建了環境之後 lint 才會開始說話。

用詞跟 C4 對齊，注意兩個容易搞混的：

- **服務（Container）** 是**會接收請求的程序**——Redis、Consul、你的 API。不是 Docker 容器。
- **機器（Deployment Node）** 才是實體機／VM／Linux 容器。站點（機房）也是機器的一種，用來裝別的機器。

## 順序

前面的是後面的前提，跳過去會失敗：

```
1. describe          先看現在有什麼，不要重複建立
2. system            系統
3. container         服務
4. endpoint_def      接點定義（契約要指定連到哪一個）
5. relationship      契約：誰連誰
6. environment       環境
7. create_nodes      機器與落地
8. add_connection    在環境裡實現契約
9. lint              收工前確認
```

第 4 步最容易被跳過。**沒有接點定義就建不了契約，也建不了機器**——
`create_nodes` 需要知道那台機器上的服務怎麼被連上。

## 讀資料的時候要問自己的事

原始資料通常是人寫給人看的，會漏掉模型需要的東西。缺什麼就**問使用者**，
不要自己編：

- **這個服務怎麼被連上？** port？protocol？（→ 接點定義）
- **有幾個環境？** 資料裡常常只寫 prod，但 uat／dev 也要建
- **中間有沒有經過 F5 之類的設備？** 資料裡常寫「A 連到 B」，實際上是「A → F5 → B」
- **同一個服務有幾台？** 「三台 Apache」要建三台，不是一台
- **有沒有主中心／異地？** 有的話要建站點，並且用 `redis-* @ dc-main` 限定範圍

編一個 IP 出來比留白更糟：留白 lint 會叫（L006），編的看起來像真的。

## 三個一定會踩的坑

### ① 經過設備要拆成兩段

資料上寫「Apache 連到 Gateway，走 F5」。模型裡是**兩條連線，同一個契約**：

```
add_connection  relationship: apache-to-gateway
                from: apache-*        to: f5-01 : vip-gateway
add_connection  relationship: apache-to-gateway
                from: f5-01           to: gateway-*
```

只建第一段的話，`lint` 會說 L002 走不通——那正是它該抓的。

### ② 多台用萬用字元，不要一台一條

三台 Redis 建**一條** `redis-*` 的連線，不是三條。工具會自動幫你算 `expect`。

一台一條的話，之後每加一台機器都要記得補一條連線——而「忘記補」正是
這個工具存在要抓的東西。

### ③ 同站優先加跨站備援是四條

「主中心優先走主中心，異地優先走異地，某個中心出問題才交叉」在模型裡是四條：

```
gateway-* @ dc-main → channel-* @ dc-main     正常
gateway-* @ dc-dr   → channel-* @ dc-dr       正常
gateway-* @ dc-main → channel-* @ dc-dr       fallback: true
gateway-* @ dc-dr   → channel-* @ dc-main     fallback: true
```

寫成一條扁平的 `gateway-* → channel-*` 也會通過 lint，但那樣就**看不出
跨中心那條路有沒有真的開通**——而防火牆規則最常漏的就是那條。

## 錯誤訊息是給你看的

工具的錯誤都附上候選與下一步。照著做，不要重試同一件事：

```
找不到系統 shopp。有的是：shop
服務 redis 還沒有任何接點定義。先 create endpoint_def。
服務 redis 有 2 個接點，要指定哪一個：client-port、cluster-bus
```

## 收工

1. 跑 `lint`，把還沒解決的處理掉
2. **不會自動存檔**——用人話跟使用者說你建了什麼、還剩下什麼沒解決
3. 讓他在畫面上看過再存。他也可以按 ⌘Z 退掉你做的每一步

剩下 lint 沒解決不是失敗。有些東西**只有他知道**（實際 IP、要不要走 F5、
某個服務在 uat 是不是真的不部署）。把問題留在那裡讓他回答，
比你猜一個答案好——猜的那個會看起來像真的。
